<h2>Two panels, one content instance each</h2>
<p>Left Sidebar Widgets adds native widgets after the library tree and optional left menu. Right Sidebar uses the existing sidebar-1 area, so upgrading does not rename or discard its widget instances. Footer Widgets is optional and remains below the entire page shell.</p>
<p>Use Appearance &gt; Widgets or the Customizer. Both core block widgets and classic widgets are supported. An empty left widget area supplies search; an empty right area supplies site information, feed access, and recent articles. Both panels are enabled by default on every template. The Customizer can explicitly disable either panel.</p>

<h2>Keep navigation roles distinct</h2>
<p>Assign the Primary Menu to global site navigation. Assign Left Sidebar Menu only when an additional hand-curated library menu is useful; it does not replace the native Page tree. Footer Menu is for secondary destinations. None of these menus is the article's table of contents.</p>

<h2>Choose widgets for a reference library</h2>
<p>Useful right-panel choices include a short collection description, taxonomy links, a search block, recent updates, and feed links. Keep the number deliberate. A long list still scrolls inside its panel, but the reader should not have to hunt through unrelated material.</p>

<h2>Reading preferences stay native</h2>
<p>Appearance &gt; Customize &gt; Docspress offers a comfortable or compact reading measure, standard or large body text, article-contents depth, and the last-modified label. These are theme settings, not a new content model. Page content, menus, excerpts, parents, and widgets remain ordinary WordPress data.</p>
